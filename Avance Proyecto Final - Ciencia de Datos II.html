1. Descripción del proyecto original

Operation Suite es una plataforma web para centralizar la administración y supervisión de herramientas de producción gráfica que se ejecutan localmente en Adobe Illustrator. Su finalidad no es procesar arte en la nube: controla de forma segura quién puede utilizar cada herramienta, desde qué estación autorizada y dentro de qué cuenta o workspace.

La solución integra una aplicación web, Firebase Authentication, Cloud Firestore, Cloud Functions, un Local Bridge de alcance local y un panel CEP para Adobe Illustrator. Los motores de Clean Vector PRO y Sep Maker PRO permanecen ejecutándose en la computadora del artista. Operation Suite administra cuentas, usuarios, membresías, roles, equipos, workspaces, herramientas, licencias, asignaciones y estaciones de trabajo.

Problema original que resuelve. En un entorno de producción gráfica, las herramientas, automatizaciones, configuraciones por cliente y accesos pueden estar fragmentados entre estaciones y usuarios. Operation Suite aporta autorización centralizada, aislamiento por workspace, estandarización, trazabilidad y telemetría operacional segura.

Arquitectura operacional

Super Administrator → Web App / consola administrativa → Cloud Functions auditadas → Firestore con acceso default-deny → catálogo autorizado de la estación → Local Bridge local → panel CEP → Clean Vector PRO o Sep Maker PRO → resultado sanitizado → ExecutionEvent V1 y agregados diarios → tableros según rol

Por privacidad, Operation Suite no registra ni analizará nombre, ruta o contenido de archivos, arte, configuraciones técnicas de clientes, direcciones MAC, correos personales, credenciales ni secretos. La telemetría conserva únicamente datos operacionales mínimos y autorizados.

2. Problema seleccionado

Operation Suite registra ejecuciones de herramientas con duración, resultado, timestamps, versión, workspace y estación autorizada. Estos datos informan qué ocurrió, pero no identifican automáticamente si una ejecución fue inusual ni cuál entidad debe revisarse primero.

Una ejecución puede terminar con success y, aun así, tardar mucho más que su comportamiento normal. Por ejemplo, una acción de Sep Maker PRO que normalmente toma entre 8 y 15 segundos podría tardar 47 segundos; el estado de éxito no revela esa posible degradación.

Pregunta central: ¿Cómo puede el análisis de telemetría operacional permitir la identificación temprana de comportamientos anómalos y la priorización de workspaces, dispositivos o herramientas que requieren intervención dentro de Operation Suite?

3. Objetivos

Objetivo general

Construir Operation Suite Intelligence, un componente de Ciencia de Datos que analice telemetría operacional segura para detectar anomalías, calcular salud operativa y priorizar workspaces, dispositivos y herramientas que requieren atención dentro de Operation Suite.

Objetivos específicos

  1. Diseñar un dataset híbrido, trazable y privado a partir de telemetría operacional y datos sintéticos reproducibles.
  2. Implementar un proceso ETL que extraiga, normalice, limpie y prepare los datos para análisis, entrenamiento, evaluación y visualización.
  3. Realizar análisis exploratorio de ejecuciones, duración, resultado, herramientas, workspaces, plataforma y tendencias temporales.
  4. Identificar y evaluar una técnica de detección de anomalías basada en Isolation Forest frente a una línea base estadística robusta.
  5. Diseñar un Operational Health Score y un Priority Engine explicables que apoyen decisiones administrativas sin evaluar el desempeño individual de empleados.

4. Dataset

Fuente y tipo

La fuente operacional es el contrato implementado ExecutionEvent V1. Para el avance se generó un dataset reproducible de 1,440 ejecuciones sintéticas, distribuidas en 90 días y dos grupos homogéneos: Clean Vector PRO / CLEAN ART y Sep Maker PRO / Apply. La estructura también admite ejecuciones reales controladas cuando sean autorizadas.

5. Proceso de Ciencia de Datos

5.1 Obtención

La obtención se diseñó para partir de eventos de telemetría autorizados y de las colecciones mínimas necesarias para contextualizarlos: ejecuciones, agregados diarios, estaciones, workspaces y catálogo de herramientas. En esta entrega se utiliza un generador determinístico con IDs opacos, semilla documentada, patrones por herramienta y anomalías conocidas. No se conectó a Firebase productivo ni se leyó contenido de Illustrator.

5.3 Limpieza

La limpieza diferencia un dato inválido de una anomalía válida. Se rechazan registros con identificadores o categorías fuera de la allow-list, duplicados conflictivos, campos obligatorios ausentes, timestamps no interpretables, finalización anterior al inicio, duración negativa o duración mayor al máximo contractual de doce horas.

Una ejecución lenta, fallida o cancelada que cumple el contrato no se elimina; podría contener precisamente la señal operacional que se desea detectar. Los nulos opcionales se conservan como ausencia explícita y los IDs opacos se excluyen de las features directas para evitar sesgo por alta cardinalidad.

6. Modelos utilizados — algoritmo identificado

Tipo de problemaAprendizaje no supervisado para detección de anomalías operacionales.
Algoritmo identificadoIsolation Forest, entrenado inicialmente por grupos homogéneos de herramienta y acción.
Variable objetivoNo aplica como objetivo operacional tradicional. La etiqueta expected_anomaly existe solo para evaluar el dataset sintético después del scoring.
Feature iniciallog_duration, derivada de duration_ms. Las variables temporales, plataforma y versión serán candidatas únicamente si una ablación temporal demuestra mejora.
Features excluidasstatus, error_code, workspace_id, device_id, account_id y actor_uid; se usan para EDA, explicación o agrupación, no para que el modelo aprenda identidades o “fallo = anomalía”.
EvaluaciónSeparación cronológica 70/30, Precision, Recall y F1; comparación obligatoria con baseline robusto MAD/IQR.
Resultado preliminar y criterio de rigor: en el dataset sintético univariado, MAD/IQR superó a Isolation Forest. Por ello, ambos se conservarán como comparación y ninguna alerta automatizará decisiones. Isolation Forest sigue siendo el algoritmo seleccionado para la clase por su capacidad de identificar patrones inusuales sin requerir un historial real ampliamente etiquetado.

Conclusión del avance

El avance cumple con la definición del problema, objetivos, dataset, diccionario de datos, ETL, limpieza, EDA y la identificación del algoritmo solicitado. El valor agregado de Operation Suite Intelligence consiste en transformar telemetría segura en señales explicables: qué ejecución se comportó de forma inusual, qué workspace, dispositivo o herramienta requiere atención y por qué.

La siguiente etapa será validar con datos REAL_CONTROLLED, ampliar las visualizaciones académicas y, únicamente tras aprobación técnica separada, evaluar la integración de resultados derivados al dashboard exclusivo del Super Administrator.
